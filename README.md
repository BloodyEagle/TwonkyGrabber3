# Twonky Grabber

Поиск и скачивание медиафайлов (изображения, видео) с Twonky-серверов. Файлы адресуются номерами
`{base}/disk/O0$2$20I<n>`; нумерация зависит от прошивки: подряд (шаг 1) или с шагом 256.

Архитектура: **Angular-клиент + Express-сервер** на TypeScript. Браузер не обращается к Twonky
напрямую (CORS, просроченные TLS-сертификаты) — весь трафик идёт через сервер-прокси; файлы
скачиваются на диск сервера, а не в браузер.

## Структура

```
server/                     Express-сервер (TypeScript, CommonJS)
  src/config.ts             все параметры (+ рантайм-конфигурация C, GET/POST /api/config)
  src/index.ts              сборка зависимостей, восстановление состояния, раздача фронта
  src/lib/http.ts           транспорт на node:http/https (rejectUnauthorized: false)
  src/lib/probe.ts          пробы: HEAD → GET Range fallback, ретраи
  src/lib/url-parser.ts     парсинг URL подключения
  src/lib/scanner.ts        сканер: seq/delta, руки, прыжки, sparse, gapfill, sweep
  src/lib/downloader.ts     очередь скачивания: пул потоков, докачка .part, нейминг _N
  src/lib/routes.ts         REST /api/* + SSE (scan/found/queue)
  src/lib/store.ts          state.json (атомарная запись, автосейв)
  test/*.spec.ts            юнит-тесты (node:test, сеть замокана)
client/                     Angular 20 (standalone, signals, SCSS, тёмная тема)
  src/app/core/services/    Api, Sse, StateStore, Files, Toast
  src/app/components/       connection-form, scan-panel, gallery(-toolbar), file-card,
                            queue-panel, settings-page
plan.md                     детальный план и дизайн-система
```

## Запуск

### Разработка

```bash
# терминал 1 — сервер (tsx watch, http://localhost:3000)
cd server
npm install
npm run dev

# терминал 2 — клиент (ng serve + прокси /api → localhost:3000, http://localhost:4200)
cd client
npm install
npm start
```

### Прод

```bash
cd server && npm install && npm run build
cd ../client && npm install && npm run build
cd ../server && npm start        # раздаёт client/dist и API на одном порту
```

Сервер ищет сборку фронта в `dist`, `dist/browser`, `dist/<name>/browser`; все не-`/api` GET
отдаются как SPA (index.html).

### Тесты

```bash
cd server && npm test            # 51 тестов (node:test через tsx)
```

### Docker

Сервер и клиент упаковываются в один образ (multi-stage: сборка Angular + сборка сервера,
тонкий рантайм). Скачанные файлы и состояние хранятся на хосте через bind volume.

```bash
# Windows
build.cmd
run.cmd

# Linux / macOS
./build.sh
./run.sh
```

`run.*` при отсутствии образа соберёт его сам, создаст каталоги `./downloads` и `./data`
и запустит контейнер на `http://localhost:3000`. Каталоги монтируются внутрь контейнера:

| Каталог хоста | Каталог в контейнере | Назначение |
|---|---|---|
| `./downloads` | `/app/server/downloads` | скачанные файлы |
| `./data` | `/app/server/data` | `state.json` (персистентное состояние) |

Порт можно переопределить переменной `PORT` (например, `set PORT=8080` в cmd или
`PORT=8080 ./run.sh`). Имя образа — `twonky-grabber` (переменная `IMAGE`).

## Окружение сервера (env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `3000` | порт HTTP-сервера |
| `DOWNLOAD_DIR` | `./downloads` | каталог скачиваемых файлов |
| `STATE_FILE` | `./data/state.json` | файл персистентного состояния |
| `STATIC_ROOT` | `../client/dist` | базовый каталог сборки фронта |

## Настройки

Все параметры (сканер, пробы, загрузчик, превью, SSE, пагинация, дефолты URL) редактируются
в UI: **Настройки → Параметры сервера** (REST: `GET/POST /api/config`). Значения сохраняются в
`state.json` и переживают рестарт; кнопка «Сбросить к default» возвращает план-значения.
Параметры с пометкой «применяется после перезапуска» (интервалы SSE, автосейв) считываются
таймерами на старте. Env-переменные (PORT и т.п.) в UI отображаются только для чтения.

Изменённые значения подсвечиваются (жёлтая рамка + `def:` — значение по умолчанию).

## Поведение

- **Подключение**: вставьте URL вида `http://host:9000/disk/O0$2$20I5000` — протокол, порт,
  путь и префикс опциональны (дефолты настраиваются).
- **Скан**: разведка 256 номеров → режим seq (шаг 1) или delta (шаг 256); руки вперёд/назад,
  прыжки после 500 промахов, разреженный поиск, плотные проходы. Сетевые ошибки (12 подряд)
  ставят скан на паузу — продолжение вручную.
- **Галерея**: пагинация, фильтр, сортировка, 4 размера превью (S/M/L/XL, редактируются).
  Клик по превью открывает оригинал; чекбокс выбирает файл, Shift+клик — диапазон.
- **Очередь**: пул потоков 1..32 (авто-подстройка по скорости или ручной слайдер), докачка
  `.part` (Range), дедуп «уже скачан» (тот же размер), суффиксы `_1.._N` при коллизиях,
  пауза/резюм, повтор ошибок, очистка завершённых.
- **Рестарт**: скан и очередь продолжаются с места (state.json, автопродолжение wasRunning).
- **Сброс состояния** (Настройки): очищает списки скана/очереди, файлы на диске не трогает.
